| 已有技能 | 在嵌入式中的复用 |

## 第一阶段：嵌入式基础（4-6 周）

### 目标

能在开发板上点亮 LED、读取按键、用串口打印，理解裸机程序是怎么跑的。

### 学习内容

#### 1. C 语言嵌入式特化（第 1 周）

你已有编程基础，不需要从头学 C 语言。重点攻这些嵌入式特有内容：

| 知识点 | 为什么重要 | 深度要求 |
|--------|-----------|----------|
| **指针与数组深入** | 嵌入式内存有限，所有音频缓冲区操作都依赖指针 | 函数指针、指针数组、指针的指针，都要能随手写 |
| **位运算** | 寄存器操作的本质——设置/清除/翻转某个位 | `\|=`, `&=~`, `^=` 成为肌肉记忆 |
| **volatile 关键字** | 告诉编译器"这个变量可能被中断改变，不要优化掉" | 理解什么场景下必须加 volatile（外设寄存器、中断共享变量） |
| **static 关键字** | 文件内函数隐藏、静态局部变量保持状态 | 嵌入式大量用 static 限定作用域，减少全局变量 |
| **结构体与内存对齐** | 寄存器映射就是用 struct 映射到固定地址 | 理解 `__attribute__((packed))` 和默认对齐的区别 |
| **函数指针与回调** | 中断回调、HAL 库的回调机制 | 理解 `void (*callback)(void)` 的语法和用法 |

**推荐资源**：
- 《C 和指针》（Kenneth Reek）——指针章节精读
- [《C 语言深度解剖》](https://book.douban.com/subject/4924719/)——嵌入式 C 的常见陷阱

**一周练习**：
- 用 C 实现一个环形缓冲区（ring buffer）——这是后续所有音频处理的基石数据结构
- 写一个链表并手动管理内存（malloc/free），理解内存碎片问题

---

#### 2. 微控制器基础（第 2-3 周）

| 外设/概念 | 学什么 | 实验 |
|-----------|--------|------|
| **GPIO** | 输入/输出/开漏/推挽/上下拉 | LED 闪烁、按键读取（轮询 + 中断两种方式） |
| **中断（NVIC）** | 中断向量表、优先级、抢占/子优先级 | 按键中断翻转 LED |
| **定时器（Timer）** | 时基、输出比较、输入捕获 | 精确定时 LED 闪烁、测量按键按下时长 |
| **PWM** | 占空比、频率、互补输出 | LED 呼吸灯、控制舵机角度 |
| **ADC** | 分辨率、采样率、参考电压、连续/单次转换 | 用电位器控制 LED 亮度（ADC 读电压 → PWM 调亮度） |
| **UART** | 波特率、数据位、停止位、校验位 | printf 重定向到串口，PC 端用串口助手查看 |
| **I2C** | 起始/停止条件、地址、ACK | 读取温湿度传感器（如 SHT30）的数据 |
| **SPI** | 4 线制、CPOL/CPHA、全双工 | 驱动一块 SPI OLED 屏幕（128x64） |

**关键工具链**：

```
开发环境：VS Code + ARM GCC + OpenOCD + CMake
芯片配置：STM32CubeMX（生成初始化代码骨架）
调试器：ST-Link V2 + OpenOCD
```

**不要用 Keil/IAR 这些传统 IDE。** 2026 年嵌入式开发的主流已经是 VS Code + CMake。Keil 的编辑体验会把你劝退。

**周末实验**：
1. 用定时器触发 ADC 采样（周期性采集电位器电压）
2. 通过 UART 把采样值实时发送到 PC
3. PC 端用你熟悉的 Web 技术写一个小页面，用 Web Serial API 接收数据并用 Canvas 画实时波形

#### 3. 数据手册阅读能力（贯穿全程）

这是嵌入式工程师的核心技能——**你现在依赖框架文档（MDN、Apple Developer Docs），嵌入式依赖芯片手册。**

| 文档类型 | 内容 | 何时查阅 |
|----------|------|----------|
| **Datasheet** | 电气特性、引脚定义、封装、供电范围 | 原理图设计、选型时 |
| **Reference Manual** | 寄存器描述、外设功能、时钟树、中断映射 | 写驱动时——你要找的就是"哪个寄存器的第几位控制什么" |
| **Errata** | 芯片已知的硬件 Bug 和 workaround | 踩坑时——你遇到的诡异问题可能已在 Errata 中记录 |
| **Application Note** | 芯片厂写的"怎么用某个外设"指南 | 第一次用某个外设时，比 Reference Manual 好读 |

**练习方法**：找一个简单外设（比如 UART），关掉 CubeMX 生成的 HAL 库代码，对着 Reference Manual 手动写寄存器配置，从零实现 printf 输出。做一次你就知道 HAL 库在干什么了。

## 第二阶段：音频硬件入门（4-6 周）

### 目标

理解数字音频的基本概念，能在 MCU 上播放和录制声音。

### 学习内容

#### 1. 数字音频基础（第 1 周）

| 概念 | 解释 | 嵌入式中的意义 |
|------|------|---------------|
| **采样率（Sample Rate）** | 每秒采集音频的样本数（44.1kHz / 48kHz） | 决定了 DMA 中断的频率——48kHz 意味着每 20.8μs 就有一个新样本 |
| **位深（Bit Depth）** | 每个样本用多少 bit 表示（16-bit / 24-bit / 32-bit） | 决定了数据的动态范围和缓冲区大小 |
| **PCM（脉冲编码调制）** | 最原始的未压缩数字音频格式 | 你在 MCU 里处理的全部是 PCM 数据流 |
| **I2S 协议** | Inter-IC Sound，数字音频芯片间的标准总线 | MCU ↔ CODEC 之间的高速串行数据通道 |
| **CODEC** | 编解码芯片，负责数字↔模拟转换 | 麦克风（模拟）→ CODEC 的 ADC → I2S → MCU → I2S → CODEC 的 DAC → 耳机（模拟） |
| **信噪比（SNR）** | 信号与噪声的比值（dB） | 选 CODEC 的关键指标，>90dB 算不错 |
| **总谐波失真（THD）** | 输出信号相对于输入的失真程度 | 音频产品的核心品质指标 |

**不需要啃《数字信号处理》课本。** 第一遍知道概念名字和它们在系统中的位置就行，遇到具体问题再深挖。

**推荐资源**：
- [Monty 的视频：Digital Show & Tell](https://xiph.org/video/vid2.shtml)（Xiph.org，24 分钟，讲清采样和位深的本质）
- I2S 协议规范（飞利浦 1986 年发布，网上随处可找到中文解读）

---

#### 2. I2S 外设配置（第 2-3 周）

**学习路径**：

```
第 2 周：软件模拟 I2S 协议
  ├─ 用逻辑分析仪抓真实的 I2S 波形，理解 WS/SCK/SD 三根线的时序
  ├─ 手动写代码模拟 Master 模式的 I2S 时序（用定时器 + GPIO）
  └─ 验证：逻辑分析仪抓出和标准 I2S 一致的波形

第 3 周：使用 MCU 硬件 I2S 外设
  ├─ 配置 STM32 的 I2S/SAI 模块（CubeMX 生成基础配置）
  ├─ 配置 DMA 双缓冲（Ping-Pong Buffer）
  └─ 连接 MEMS 麦克风（I2S 输出型）或 CODEC 芯片
```

**关键配置参数**：

| 参数 | 典型值 | 说明 |
|------|--------|------|
| 采样率 | 48000 Hz | 最通用的选择，CD 是 44100 |
| 位深 | 16-bit 或 24-bit | 16-bit 数据最简单，24-bit 音质更好但处理更复杂 |
| I2S 模式 | Philips 标准 | 最常见的模式，WS 拉低 = 左声道 |
| DMA 模式 | 双缓冲循环模式 | 处理一半时 DMA 自动填充另一半，避免数据断流 |
| 缓冲区大小 | 512 或 1024 样本 | 太小→中断太频繁；太大→延迟太高 |

#### 3. 音频数据流（第 4-6 周）

**实现一个"对讲机"程序**——这是第二阶段的终极练习：

```
[MEMS 麦克风] → I2S RX → DMA → Ping-Pong Buffer A/B
    → CPU 处理（加增益/简单滤波）
    → DMA → I2S TX → [I2S DAC / 耳机功放] → 耳机
```

**架构设计**：

```
高优先级（定时器中断）：
  ├─ DMA 半传输完成中断 → 处理 Buffer A 前半段
  ├─ DMA 全传输完成中断 → 处理 Buffer B 前半段
  └─ 触发信号量，通知处理任务

低优先级（主循环或 RTOS 任务）：
  ├─ 等待信号量
  ├─ 处理 Buffer A/B 前半段刚刚填满的数据
  └─ 应用 DSP 效果（增益、EQ 等）
```

**关键工具**：逻辑分析仪（淘宝 50 元级别就行）——抓 I2S 波形确认数据在总线上正确传输。**音频调试没有逻辑分析仪 = 蒙眼飞飞机。**

## 第三阶段：嵌入式 DSP 实战（8-12 周）

### 目标

在 MCU 上跑实时音频处理算法。

### 学习内容

#### 1. 实时音频处理基础（第 1-2 周）

| 概念 | 解释 | 代码模式 |
|------|------|----------|
| **环形缓冲区** | 固定大小的 FIFO，写指针追上读指针时覆盖旧数据 | `buf[wr_ptr++ % SIZE] = data;` |
| **双缓冲/乒乓缓冲** | DMA 填 Buffer A 时 CPU 处理 Buffer B，然后交换 | 两个数组 + 一个标志位切换 |
| **实时性约束** | 48kHz 采样率下，每个样本的处理预算只有 ~20.8μs | 必须避免：malloc、printf 在中断中、浮点除法的软件模拟 |
| **定点数运算** | 没有 FPU 的 MCU 上用整数模拟小数（Q 格式） | `int16_t q15_mul(int16_t a, int16_t b)` |

**第一周实验**：不用 HAL 库，手动实现双缓冲 DMA 音频采集 + 播放回路。

**第二周实验**：用 CMSIS-DSP 库实现一个 FIR 低通滤波器，验证高频被正常滤除。

---

#### 2. CMSIS-DSP 库（第 3-4 周）

ARM 官方的数字信号处理库，针对 Cortex-M 内核高度优化。

| 功能模块 | 包含什么 | 在音频中的用法 |
|----------|----------|---------------|
| **滤波** | FIR、IIR、双二阶（Biquad）、LMS | EQ、分频器、自适应降噪 |
| **FFT** | 实数/复数 FFT、逆 FFT、幅度/相位 | 频谱分析、频域处理 |
| **矩阵运算** | 矩阵乘法、求逆、转置 | 自适应滤波、波束赋形 |
| **统计** | 均值、方差、RMS、最大/最小值 | 音量检测、动态范围计算 |
| **数学** | sin/cos/sqrt（SIMD 加速）、对数 | 合成器、dB 转换 |

**实践项目**：实现一个实时频谱分析仪

```
音频采集（I2S DMA）→ 加窗（Hanning）→ 1024 点 FFT → 幅度计算
→ 串口发送频谱数据 → PC 端 Web 页面实时画频谱瀑布图
```

**你的前端优势在这里爆发**：用 Web Serial API + Canvas/WebGL 写一个桌面频谱可视化工具，实时显示波形、频谱曲线、瀑布图。这是纯嵌入式工程师做不到的——他们只能看串口打印的数字。

两端代码结构：

```
嵌入式端（C）：
  loop:
    DMA 填充一半 → CMSIS-DSP FFT → 计算 512 个频点幅度
    → 简单压缩（log 映射）→ UART 发送帧头 + 512 字节

PC 端（你的老本行）：
  navigator.serial.requestPort() → 读取串口数据
  → Canvas 绘制条形频谱图 + 下方滚动瀑布图
  → 60fps 实时渲染
```

#### 3. FreeRTOS（第 5-6 周）

| 概念 | 和前端/移动端的类比 |
|------|-------------------|
| **任务（Task）** | 类似于独立运行的线程/Worker |
| **优先级** | 类似 iOS 的 QoS（`.userInteractive` > `.background`） |
| **队列（Queue）** | 类似生产者-消费者模式中的 Channel |
| **信号量（Semaphore）** | 类似 Promise 的 resolve——"这个资源可用了" |
| **互斥锁（Mutex）** | 类似 `@synchronized` / `synchronized` 代码块 |

**音频任务的 RTOS 设计**：

```
采集任务（优先级：最高，实时）
  └─ 等待 DMA 中断 → 从 I2S 读数据 → 通过队列发给处理任务

处理任务（优先级：高）
  └─ 等待队列中有数据 → 跑 DSP 算法 → 通过队列发给输出任务

输出任务（优先级：高）
  └─ 等待处理完的数据 → 写入 I2S TX DMA 缓冲区

UI 任务（优先级：低）
  └─ 读取按键/旋钮 → 更新 EQ 参数 → 通过队列发给处理任务

监控任务（优先级：最低）
  └─ 每隔 100ms 检查 CPU 负载、DMA 是否断流、打印调试信息
```

#### 4. DSP 基础理论（按需学习，贯穿第 7-12 周）

**不要从头啃奥本海姆的《信号与系统》。用什么学什么。**

| 想实现什么 | 需要学的 DSP 知识 | 推荐资源 |
|-----------|-------------------|----------|
| **三段 EQ（低/中/高频可调）** | 双二阶滤波器（Biquad）设计、滤波器系数计算 | EarLevel 的 Biquad 教程 + [RBJ Audio EQ Cookbook](https://www.w3.org/TR/audio-eq-cookbook/) |
| **实时频谱显示** | FFT、加窗函数（Hanning/Hamming）、频谱泄漏 | [The Scientist and Engineer's Guide to DSP](http://www.dspguide.com/) 第 8-12 章（免费在线） |
| **动态范围压缩器** | 包络检测器（RMS vs Peak）、attack/release 时间常数 | [Hack Audio](https://www.hackaudio.com/) 的压缩器章节 |
| **简单降噪** | 频谱减法（Spectral Subtraction） | 论文经典版 + STM32 实现案例 |
| **混响效果** | 梳状滤波器 + 全通滤波器（Schroeder 混响器） | [Physical Audio Signal Processing](https://ccrma.stanford.edu/~jos/pasp/)（Julius Smith，免费） |
| **采样率转换** | 升采样（插值 + 低通滤波）、降采样（低通滤波 + 抽取） | [Multirate Signal Processing](https://www.dsprelated.com/freebooks/) |
| **延迟/回声效果** | 环形缓冲区 + 衰减系数 | 最简单——几行代码就能实现 |

## 第四阶段：音频产品实战（8-12 周）

### 目标

做一个可以拿出手的、有完整外壳的音频设备。

### 选择你的方向

#### 方向 A：无线音频（蓝牙音箱/耳机）

| 学习点 | 内容 |
|--------|------|
| **蓝牙协议栈** | ESP32 自带 BLE + Bluetooth Classic，免费使用 |
| **A2DP 协议** | Advanced Audio Distribution Profile——蓝牙音频传输的标准协议 |
| **音频编解码** | SBC（强制支持）、AAC（可选）、了解它们的有损压缩原理 |
| **系统架构** | 蓝牙接收 PCM → I2S → CODEC DAC → 耳机功放 → 输出 |

**推荐芯片**：ESP32（Wi-Fi + BLE + Classic Bluetooth + 双核 240MHz + I2S 硬件）

**最小可行产品**：
1. ESP32 作为蓝牙 A2DP Sink（接收端）
2. 手机连上 ESP32 蓝牙
3. 手机播放音乐 → ESP32 通过 I2S 输出到 PCM5102 DAC 模块
4. 插上耳机就能听

---

#### 方向 B：音频效果器（吉他/人声）

| 效果类型 | 实现难度 | DSP 知识点 |
|----------|---------|-----------|
| **增益/音量** | ⭐ | 乘法（一行代码） |
| **延迟（Delay）** | ⭐ | 环形缓冲区 + 反馈系数 |
| **回声（Echo）** | ⭐ | 多个延迟 + 不同衰减系数 |
| **失真（Distortion）** | ⭐⭐ | 软/硬限幅（clip）+ 过采样 |
| **合唱（Chorus）** | ⭐⭐ | 调制延迟线（LFO 调制延迟时间） |
| **镶边（Flanger）** | ⭐⭐ | 极短延迟 + LFO + 反馈 |
| **三段 EQ** | ⭐⭐ | 三个 Biquad 滤波器（低架 + 峰值 + 高架） |
| **压缩器** | ⭐⭐⭐ | 包络检测 + 增益计算 + attack/release |
| **混响（Reverb）** | ⭐⭐⭐ | Schroeder 混响器（4 个梳状滤波器 + 2 个全通滤波器） |
| **自动哇音（Auto-Wah）** | ⭐⭐⭐ | 包络检测 → 调制带通滤波器的中心频率 |

**推荐平台**：STM32F4/H7 系列（有 FPU + DSP 指令集）或 ESP32-S3

**硬件设计要素**：
- 输入：6.35mm 乐器接口 → 前置放大电路 → CODEC ADC
- 输出：CODEC DAC → 输出缓冲 → 6.35mm/3.5mm 输出
- UI：物理旋钮（旋转编码器 + ADC 读电位器） + OLED 屏幕显示参数
- 电源：9V 电池或 USB-C 供电

### 嵌入式 Linux 音频

当你需要这些能力时，就该学 Linux 了：
- 需要跑复杂的网络协议栈（WebSocket 服务端、MQTT Broker）
- 需要跑大型 AI 模型（TinyLlama 级别以上）
- 需要驱动彩色触摸屏 GUI
- 产品需要文件系统和数据库

| 知识点 | 内容 |
|--------|------|
| **ALSA 框架** | Linux 音频底层驱动框架——理解 PCM 设备、hwdep、controls |
| **ASoC（ALSA SoC Layer）** | 嵌入式 Linux 的音频子系统——Machine Driver + Codec Driver + Platform Driver |
| **PulseAudio / PipeWire** | 用户空间音频服务器——多应用混音、蓝牙策略 |
| **设备树（Device Tree）** | 描述硬件拓扑——在 .dts 文件中配置 I2S 接口、CODEC 节点 |
| **Yocto / Buildroot** | 构建定制 Linux 镜像，只包含你需要的组件（系统镜像 <100MB） |

**Buildroot vs Yocto 选型**：

| 约束 | 选择 |
|------|------|
| 资源受限（<64MB RAM, <16MB Flash） | Buildroot |
| 企业级产品，需要 >5 年维护 + OTA + SBOM | Yocto |
| 快速原型、边缘服务器、团队无 Linux 构建经验 | Debian/Ubuntu Core |

2026 年趋势：混合策略——

```
Buildroot 构建 bootloader/恢复分区 + Yocto 构建主应用镜像
```

per [ProteanOS](https://proteanos.com/doc/buildroot-vs-yocto-2026/) 和 [sigma-star](https://sigma-star.at/blog/2026/05/you-probably-dont-need-yocto-and-thats-fine/)。

## 推荐首个项目：USB 电容麦克风

### 为什么是这个项目

1. **音频输入链覆盖完整**：声波 → MEMS 麦克风 → I2S → DMA → MCU → USB → PC
2. **USB Audio Class 1.0 是成熟协议**，用 TinyUSB 开源库，不需要从头写 USB 描述符
3. **PC 端用你熟悉的前端技术做可视化**——Web Audio API + Canvas
4. **完成后是一个真正有用的设备**，不是又一个"开发板跑 Demo"

### 三周推进计划

#### 第一周：I2S 采集链路

**目标**：MEMS 麦克风 → I2S → DMA → 内存 → 串口打印 PCM 原始值

| 天 | 任务 |
|----|------|
| 1 | 焊接 INMP441 到开发板，CubeMX 配置 I2S + DMA，确认时钟配置正确 |
| 2 | 实现 DMA 双缓冲采集，在 Half-Complete / Full-Complete 回调中切换缓冲区 |
| 3 | 将采集到的 PCM 数据通过 UART 发送到 PC（原始 16-bit 值，Hex 格式） |
| 4 | PC 端用 Python 脚本接收串口数据，转为 WAV 文件，确认能正常播放 |
| 5 | 对着麦克风说话，用 Audacity 打开录制的 WAV，声音正常 → 采集链路通 |
| 6-7 | 整理代码、添加错误处理（DMA 溢出检测、缓冲区状态监控） |

#### 第二周：USB Audio 输出

**目标**：PCM 数据通过 USB 发送到 PC，系统识别为录音设备

| 天 | 任务 |
|----|------|
| 1-2 | 移植 TinyUSB 库，配置 USB Audio Class 1.0 设备描述符 |
| 3 | 实现 Audio 数据接口：48kHz / 16-bit / 单声道 |
| 4 | 将第一周的 DMA 双缓冲数据对接 USB Audio TX |
| 5 | 插上 USB → Windows/macOS 自动识别为"USB Microphone" |
| 6 | 用 Audacity 选择该设备录音，对比用 3.5mm 麦克风录制的效果 |

## 附录：关键概念速查

### 音频数据格式

| 格式 | 说明 |
|------|------|
| **PCM** | 脉冲编码调制，未压缩的原始音频数据。每个样本是一个幅度值。 |
| **I2S** | Inter-IC Sound，芯片间数字音频传输的串行总线标准。 |
| **TDM** | 时分复用，I2S 的多通道扩展版，一根数据线上传输 4/8/16 声道。 |
| **PDM** | 脉冲密度调制，MEMS 麦克风常用的 1-bit 输出格式，需要软件转换为 PCM。 |

### 音频处理术语

| 术语 | 说明 |
|------|------|
| **FFT** | 快速傅里叶变换，将时域信号转换到频域。 |
| **FIR 滤波器** | 有限脉冲响应滤波器，线性相位、无条件稳定、但计算量大。 |
| **IIR 滤波器** | 无限脉冲响应滤波器，计算量小、但相位非线性、可能不稳定。 |
| **Biquad** | 双二阶滤波器，IIR 的一种，在音频 EQ 中使用最广泛。 |
| **MFCC** | Mel 频率倒谱系数，语音识别最常用的特征提取方法。 |
| **DBFS** | 相对于满刻度的分贝值，数字音频中表示电平的标准单位。 |
| **THD+N** | 总谐波失真+噪声，衡量音频设备品质的核心指标。 |

### 常见坑点

| 坑 | 原因 | 解法 |
|----|------|------|
| **爆音/咔嗒声** | DMA 缓冲区切换时数据断了 | 增大缓冲区、确保处理时间 < 缓冲区时长 |
| **底噪很大** | 模拟电源不干净，或数字地/模拟地未隔离 | PCB 布局时数字地和模拟地单点连接 |
| **I2S 左右声道反了** | WS 信号极性配置错误 | 检查 I2S 标准模式 vs 左对齐/右对齐模式 |
| **DMA 配置后不触发中断** | 忘记开启 DMA 中断、或 NVIC 优先级配置错误 | CubeMX 中逐一检查 NVIC 和 DMA 中断使能 |
| **浮点运算极慢** | MCU 没有硬件 FPU，浮点被软件模拟 | 开启 FPU（如果有）、使用定点数/Q 格式、或换带 FPU 的芯片 |
| **malloc 导致 hard fault** | 堆空间耗尽或内存碎片化 | 嵌入式尽量不用动态分配，用静态数组 + 环形缓冲区 |
| **printf 在中断中卡死** | printf 不是可重入函数，在中断上下文中调用可能死锁 | 中断中只用标志位通知，主循环中再 printf |
