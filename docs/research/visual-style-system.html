Visual Baseline

克制、清晰、能长期迭代的界面基线

这份页面不模拟具体业务，而是先把视觉规则讲清楚。核心目标只有三件事： 让主操作更稳定，让信息层级更清楚，让后续每个页面都能按同一套语法继续生长。

气质关键词 极简、安静、轻专业、阅读友好、低装饰。
视觉策略 参考 Radix Colors 的语义色阶，用更稳定的实色、软底色和可读文本色建立秩序。
后续用途 这会成为项目页面改版时的统一参照，不再逐页临时决定样式。

设计原则

不先追求“有设计感”，先确保所有页面都更稳、更轻、更耐看。下面四条会直接约束后续页面实现。

Rule Set
信息优先 主标题、主操作、当前状态必须在 3 秒内被理解，装饰不能压过内容。
强调克制 主品牌蓝只用于关键动作、焦点态和轻标签，不承担大面积视觉主导。
边界统一 优先用浅边框、圆角和留白表达结构，减少每个模块都“长得很用力”。
组件可复用 后续页面新增模块时，应优先复用这里的语义令牌和基础组件样式。

排版层级

标题和说明的落差要足够明显。正文不追求大，而追求稳定、好读、可长时间停留。

Typography

Workspace

页面主标题 / 40px

区块标题 / 28px

模块标题 / 20px

正文说明 / 15px，适合表单引导与面板描述。

辅助信息 / 13px，适合注释、状态、次级说明。

排版规则 标题使用更紧凑的字距和更短的行长；说明文案控制在 2 到 3 行；统计数字和关键单词使用更高权重； 不让标签、说明、正文看起来同等重要。

标签与提示

状态样式只服务状态本身，不作为装饰。标签短、提示轻、语义单一，避免每个状态都过度喊话。

卡片、列表与空状态

结构感来自留白、边界和主次层级，而不是背景色堆叠。卡片必须有职责，列表必须易扫读。

项目落地建议

这份规范不是孤立页面，后续会直接映射回项目。下面是建议保持不变的方向，以及建议调整的地方。

Application
建议保留
  • 工作台式布局结构，继续保留明显的内容主区。
  • 统一语义令牌命名，例如 --color-primary、--color-border。
  • 卡片化模块拆分方式，便于后续页面扩展。
建议收敛
  • 减少大面积渐变和过强品牌色存在感。
  • 侧边区域从“视觉主角”退回“结构导航”。
  • 统一状态块、标签和输入焦点态，不再逐页微调。
后续把这套风格应用到项目时，建议优先处理全局设计令牌、按钮 / 表单 / 提示等基础组件， 再逐页迁移 `SideNav`、录入页、阅读页和单词库。这样改动路径最清晰，也最不容易来回返工。
